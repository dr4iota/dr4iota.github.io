These pages are for Telechore 0.6.0 — what's new in it.

Files offline

What you open on a server is stored on this device for a while, so you can browse when the server cannot be reached, and a file that has not changed is not fetched again. A file you mark “Keep offline” stays until you remove it. A file you only opened can be dropped when this device needs the room.

A folder's rows

Everything you can do with a file or folder is on its row.

  • The icon is “Keep offline”. The bookmark on the icon is outlined while the file or folder is not kept, and filled while it is. Tap the icon to switch. A file's own page has the same button. A grey bookmark means the item is kept because its folder is kept, or that the server has changed a kept copy since this device stored it. That bookmark cannot be switched from the row.
  • A line under the row says what this device has. It says “Offline”, and when, for a copy you keep, or “Cached”, and when, for a file you only opened. Next to that, “Forget” removes the copy on this device. Nothing on the server changes. When the server has a newer file, “Update” at the end of the line fetches it without opening it.
  • Keeping a folder keeps that folder and everything in it. Telechore counts the folder first, then says how many files that is and how much space they take, and asks you to confirm. Hidden files and folders (names starting with .), node_modules, disk images and files a program generated are left out. A folder bigger than 2 GB on Android, or 10 GB on a computer, is refused, and so is one that would leave this device with too little room. Files added or changed on the server are fetched the next time you open their folder. When those changes add up to more than 50 MB, “Update” on the folder's line fetches them. A file that could not be fetched is named on that line, with “Try again”. “Forget” on that line removes the folder's copies.
  • “Download” (the arrow at the end of the row) saves a copy where you choose: a folder on a desktop, and the system's “Save to…” sheet on Android.
  • “Delete” (the bin) deletes the file, or an empty folder, from the server. It asks every time. A copy you kept offline stays, in Cache.

In the sidebar's tree, a bookmark after a name marks what you keep offline.

When the server cannot be reached

If the connection drops while a folder is open — on Android this happens a few seconds after the app leaves the screen — the next page you open connects again. The status bar says Reconnecting to … until it has. If the connection needs a password or passphrase again, one that is not saved, or a one-time code, it asks on the page you are on.

A folder on that server then opens from the copy on this device. Across the page it says cannot be reached, and it says when that copy was made. Folders you never opened, and files you never fetched, are grey. “Try again” connects once the network is back.

Cache

“Cache”, in Places, lists the servers this device holds files from. Inside a server, each folder that has a copy is one row, named by its path on the server. A long path is shown with the start cut off, as in … › pi › src. Open that row to see the copies. A server's row says how much it holds in all, across how many folders and files, and how much of that is only cached and can be freed. The server's row, and each folder's row, shows when its newest copy arrived. “Forget” and “Keep offline” work here too. “Clear…” on a server's row removes everything held from that server.

Files you only opened are removed when they take more than 500 MB (200 MB on Android), oldest first. Android may also remove them when it needs room. Files you keep offline are never removed for you. When a file has changed on the server, its copy says so. It is refreshed the next time you open the file there, or when you press “Update” on its line.

Each server

On the server's “Server” tab, “Cache this server's files” is the switch for this. Turn it off and nothing from that server is stored on this device. Below the switch, the page says how much the cache takes here, with “Clear cache…”. Deleting a server removes its cache.

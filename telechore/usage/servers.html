Telechore Usage What's new Play Feedback

These pages are for Telechore 0.5.2 — what's new in it.

Servers

A server is a saved connection: where the machine is, who you are on it, and how to log in.

On the start page, the button under Open a folder… reads Add a server while you have none and Manage servers once you have one. The Servers heading below it has the same two as icons: the plus opens the form for a new server, and the sliders open the list.

The page lists your saved servers, one row each: a green dot when it is connected, its label, its id and where it is, and on a line of its own the server it goes through, if any. From 700 pixels wide the rows sit in two columns. A phone turned on its side stays on one column. Tap a row to open it. At the row's end, New terminal (a terminal with a plus) opens a new terminal on that server, and Delete (a bin) removes it. Add a server is under the list, with Import… and Export… under it.

Above the list, Servers and Keys switch between your servers and the keys on this device (see Keys). Below a server or a key, the same row says where you are and has a way back up: ‹ Servers, ‹ Keys, or the server you came from. That row is hidden where a list beside you already shows the way back: from 1000 pixels beside a saved server or a key, and from 700 beside a key. The switch then sits in that list. When Keys is open over a server, Continue is the way back and the list only moves between keys.

A server with terminals you left open (see Keep in the terminal) lists them under its row as numbered chips: a green dot for one that is running, an amber dot and ended for one whose shell has ended. Tap a chip to go back to that terminal; on a desktop, one in a window of its own is listed too, with a window mark, and its chip brings that window forward.

Delete asks first. It removes the server from this device and closes its connection and any terminals you left open on it. A saved password is mentioned, and removed, only when this server has one; a password held until the app closes is mentioned as that. A key this app holds is removed only when no other server uses it; otherwise it stays under Keys. A key file on this machine is left where it is. The question names any server that goes through this one, which then connects directly. Nothing on the server itself changes.

A server's folders

A server's folder is browsed like one on this device (see Tree and sidebar). Its header has New folder and Upload, which takes files from the system's picker, on a desktop and on Android, and never replaces a folder with a file. Each row ends in Delete; a file's also has Download, and its icon and the line under it are what this device keeps of it (see Files offline).

A server that offers no file access (SFTP) still logs in: its terminal opens, and its row says This server offers no file access (SFTP). Its terminal still opens. in place of its folders. Tapping it for its folders says the same, with Open terminal.

A folder whose connection has dropped connects again on its own when you next use it. On a phone that happens often: Android cuts the network a few seconds after the app leaves the screen, including while you choose files to upload. A download cut off that way picks up where it stopped once the app is back.

The free edition and Pro

A copy installed from an app store is the free edition, which saves a few servers: two from Google Play, four from the Microsoft Store. Where the store sells it, Unlock Pro saves as many as you like, for one payment with no subscription, and Restore purchase gets it back on a new device or after a reinstall. Google Play sells Pro; the Microsoft Store does not yet, so a copy from there keeps its four.

A copy downloaded as a file, such as the Windows .exe or an APK, has no store to buy from and no limit.

Past the limit, servers you already have keep working and can still be edited and deleted; only adding another needs Pro, where the store sells it. The free edition also keeps that many terminals running after you leave them (see Keep in the terminal); keeping more running needs Pro too, where the store sells it. Files, the terminal and keys are free either way.

Moving servers to another device

Export… on the list shows a QR image for another device running Telechore to scan. Tick what to include: which servers, their host keys, the passwords and passphrases saved on this device, and any key this app made that those servers use. A key this app did not make is never included in a configuration code, and the sheet names any server that will arrive without its key.

The meter shows how much fits. It measures size, not servers: a short host name with no host key takes a third of the room of a long one with a key. The limit is well below what a QR image can hold, because a denser image is harder to scan.

The password beside Export encrypts the code, and you type the same one on the other device. The box is there when the code carries a password, a passphrase or a key; it is optional, and any length will do, and the sheet warns you when it is empty or short, but still lets you go ahead. When there is no password, the sheet says so: anyone who photographs the QR image has what is inside. A code with only servers and host keys has no password box and needs none: all it reveals is each server's host, user and starting folder, how it logs in — by password, a key, or the SSH agent — and, from a computer, your user name on it as the sender.

The QR image stays on screen for a minute; closing the sheet removes it sooner. The other device can read the code for three minutes if it was scanned, and for fifteen if it was pasted as text, since text is usually sent by email or message. Nothing is written to disk on either device. The time limit stops the code being used again later, but it does not help against a photo someone has already taken: a photo can be turned back into text and pasted. Against that, only the password protects you.

Copy as text is beside the QR image on every device. The QR image is for a device in front of you; the text is for one that is not, and it is the only way to get a code from a phone to a desktop. It is the same code, and the same password opens it.

Import… reads a code. On a device with no servers yet, the same Import… is on a line above the first form. Paste the code or scan it, and before anything is saved the next screen shows what the code holds: one row per server, with its state, then the host keys, secrets and keys that came with them. Untick anything you do not want.

Each server row has a state:

  • new: this device does not have the server. It is saved as it arrived.
  • already here: the id is taken. A free one is offered, such as prod-web-2, to keep both; or type the old name back to overwrite the one you have.
  • arrives without its key: the server uses a key the other device did not make, so the key is not in the code. The server is saved with a password login; choose a key under its Login afterwards. If it overwrites a server already here, it keeps that server's key.

A row can be both already here and without its key; the label shows the first and the note under it the second.

Host keys are imported only for hosts this device has no key for yet. A host you have already verified keeps its key, whatever the code says.

If a key in the code has the same name as a different key on this device, it is saved under a free name, and the servers that use it are pointed at the new name. The same key arriving twice is saved only once.

In the free edition, servers over the limit arrive unticked, and the sheet says which and why. A renamed server counts as new; overwriting an existing one does not.

Nothing is saved until you press Import, and Cancel discards the code.

A server that a computer names only by its SSH alias travels with what the alias says there written in: its host, port, user, and a jump host that is one of the servers in the same code. A phone has no ~/.ssh/config, so it keeps those and drops the alias, and the import says so. A computer that has an ssh config keeps the alias even where its config does not name it, and dials what came with the server. The alias's key files stay on the computer it came from, so such a server asks for a password. A server the alias reaches by ProxyCommand travels with no host unless you chose Through or Directly, since the app does not run the command; the phone says it will not connect until it has a host or Through.

Copying servers from an ssh config

Import… also reads an ssh config. On a computer, Read ~/.ssh/config reads your own; Choose a file…, on any device, reads one you pick. On a phone, you can also open ~/.ssh/config on a server in the file browser and press Import servers on the line under its header. That line shows on a file named config in a folder named .ssh or ssh, and on one named sshconfig or ssh_config. On a computer with no servers yet, a line above the first form offers the hosts of your own ~/.ssh/config too.

Each Host line with a plain name becomes a server, named after its first name. It is a copy: the host, port, user, key and jump host are written into the server, and later edits to the file do not reach it. To follow the file instead, type the alias into the SSH alias box. Only the blocks that name a host are read for it: wildcard blocks such as Host * or Host *.lan, the lines above the first Host, and Match blocks are skipped, so nothing they set is copied; a row says what one would have set for it, such as the User or IdentityFile many configs keep under Host *. A chosen file's Include lines are not followed; your own ~/.ssh/config's are.

The next screen lists the hosts before anything is saved, each with what it will do:

  • Its login, as ssh would choose it: the first key file the host names that is on this device; otherwise the SSH agent, if one is running with keys and the host does not say IdentitiesOnly yes; otherwise, if the host names no key, the first of ~/.ssh/id_* that exists; otherwise a password. A key file that is not on this device is named, and the server asks for a password until you choose a key under its Login.
  • Through, where its own ProxyJump, if it is the one ssh keeps rather than a wildcard block's that comes first, is one host that is in the same file or is one of your servers, and any user or port written on it is the one that server logs in with. Anything else, two jump hosts, a jump host that is not a server, or one that is not plain (quotes, spaces, shell characters), is said on the row, to be set by hand. If the jump host is a row you untick, the row going through it says it will connect directly.
  • not copied, for a host ssh reaches by ProxyCommand, whether its own block or a wildcard block such as Host * sets it: the app does not run the command, and going straight to its host name may reach another machine. As in ssh, whichever of ProxyCommand and ProxyJump comes first for a host is the one used; a host reached by its jump follows the rule above. Add it by hand with Through, or type its alias into a server's SSH alias box, where the dial says the same.
  • saved as …, where one of your servers already reaches the same host, port and user (no user being your own login name), or names that alias. It cannot be ticked, so a copy never overwrites a server you set up.

A name already taken by a different server is offered a free one, as for a code. In the free edition, hosts over the limit arrive unticked. Nothing is saved until you press Copy.

A server

A server opens as a summary: its id, Connected or Not connected with Disconnect beside it, greyed while there is no connection, and its open terminals with New terminal at the end. Under that are four parts, each with a line saying what it holds: Name & address, Login, Terminal and Files on this device, then Last connection once the server has been connected to since the app started, and Delete server… last, which asks first. On a phone a part opens in place, one at a time; a new server opens Name & address and Login together. In a window 700 pixels wide or more the summary sits beside the part you choose, and from 1000 pixels the server list is beside both. A phone turned on its side keeps the phone's layout.

Close, Test and Save (Add server for a new one) are in a bar at the bottom, above the keyboard on a phone. The line above them says what stops Save, what is happening (Testing…, Saving…), how a test went, or that there are unsaved changes. Add server waits for a host and a label, and on Android a user.

If a value is refused, that line says how many problems there are and in which boxes; tap it to go to the next one. A closed part with a problem says so in red.

A button short of room on its line drops its words before its icon, and only when that keeps it on the line.

Import, Export, receiving a key code, showing a key as a code and installing a key on a server open over what you were doing: as a box over the page in a window 700 pixels wide or more, and over the whole screen on a phone. Closing one with Cancel, Done, ✕, Escape or Back leaves you where you were.

The fields

Under Name & address:

  • Label is the name you see. Id, beside it, is the name the app uses internally. It starts out based on the host, or on the SSH alias when that is all there is, and it cannot change once saved: a new id would make a second server.
  • Host is what you would type after ssh.
  • User may be empty on a desktop, and then your local user name is used, as with ssh host. On Android it is required, since a phone has no user name to fall back on.
  • Port is usually best left empty. That lets an alias in ~/.ssh/config set the port; otherwise 22 is used, which is what the greyed 22 means.
  • Initial path is where browsing and a terminal start. ~ suits most accounts.
  • Through reaches the server by way of another server you saved, a jump host or bastion, as ssh -J does. Its host is then the address as that server sees it. Directly is the default. Where the SSH alias already names a jump host (ProxyJump), the first choice is As the alias says, and choosing a server or Directly goes another way. Deleting a server others go through says which, and they connect directly from then on.
  • SSH alias is any name ssh would take: a Host from ~/.ssh/config, or a host name, which then gets the config's matching blocks such as Host *. It fills in any empty host, user and port; values you type take priority. Desktop only, since a phone has no ~/.ssh/config. Its ProxyJump is followed too: a jump host that is one of your servers connects as that server. See Where ~/.ssh/config is read below.

Under Files on this device:

  • Cache this server's files, a switch, keeps what you open on this server on this device. Under a line, how much it takes and Clear cache…. It is on by default; see Files offline.

Under Terminal, with Font, Behaviour and Advanced folded until you open them. Each setting is named with a short note under its name that says what it does as set, and on/off settings are switches:

  • Size is one of three.
    • Fit the screen: programs get whatever fits, about 33 columns on a phone held upright, too narrow for tmux or htop.
    • Fixed at a number of columns and rows, in Columns and Rows under it, with 80×24, 100×30 and 132×43 a tap away. Programs always see that size; you zoom and pan around it.
    • Fixed columns: the columns fill the width, and programs get as many rows as fit at that size. The rows change when the screen does (the keyboard, turning the phone) and when you zoom. You can pan and zoom across, never up or down: the rows always fill the screen.
  • View, for Fixed and Fixed columns, is Flat (the terminal pans and zooms as a whole) or Lens (the whole terminal stays on screen, full size round where you are and squeezed toward the edges). Under Lens, Focus width and Focus height set how much of the screen is at full size; see the lens. Largest zoom, under it, is how far you can zoom in, as a multiple of the default type size: 1× to 5×, 2× unless you change it (32 px at 16 px), and never less than the screen's Fill, so on a large screen you can always zoom to where Reset view goes. Under Lens it is the part at full size that zooms that far.
  • Start by decides how the terminal opens, and where Reset view goes:
    • Fit: the whole grid in view, one side meeting the screen's edges and room left on the other. Under Lens nothing is squeezed at Fit.
    • Fill (Fixed only): the screen covered, one side meeting its edges and the other cropped — under Lens, the edges squeezed instead. For Fixed columns fit and fill are the same picture, so it is not offered.
    • With nothing chosen, Flat opens at Fit and Lens at Fill; what you choose is kept when you switch between them.
    • Default type size, the one under Font, to pan around.
    • Saved view: the view you saved from the terminal's keyboard menu (the wrench, then Save under Zoom and position), one for each shape — portrait, landscape, and a desktop window that does not fill the screen: its type size and where it was panned, ↔ horizontally and ↕ vertically. A shape with none saved opens at the default type size; ✕ forgets one. Fit is the default. With Fit the screen there is nothing to choose: it always opens at the default type size.
  • Position, two rows in one box, says where the terminal sits when it opens and when Reset view puts it back: where it rests when it leaves room on the screen, and which part shows when it is cropped: Top, Middle or Bottom, and Left, Center or Right. With Fixed columns the rows fill the screen, so vertically it only places what is left below one row. Bottom left is the default, which keeps the last line next to the keyboard. With Bottom, spare room goes above the terminal, and a crop takes off the top. With Middle or Center it's split evenly. It does not limit where you can pan.
  • Typeface is the device's own monospace, System, or JetBrains Mono, which comes with Telechore and looks the same everywhere. With JetBrains Mono, Weight sets how heavy the text is, from Thin to Medium; Book is the default. Lighter text covers less of a keyboard behind it. The system font has no weights, so Weight is greyed with it.
  • Type size, beside Weight, is the default type size: 16 pixels unless you change it. It is the size Fit the screen draws at, so it decides how many columns and rows programs get. With a fixed size it is the size Start by opens at when it says so, and where an orientation has no saved view. Greyed under Fit and Fill, which size the type to the screen.
  • Follow the cursor keeps the cursor on screen for a short while after you type, so you see the answer. A cursor a program moves on its own leaves the view where you put it.
  • Taps as mouse clicks decides what one finger does where a program is listening for clicks. When it is off, one finger always selects and scrolls. The extra keys send keys either way.
  • Keyboard opens this many rows up sets how many shell rows stay visible below the app's keyboard when it opens. Raise it to keep a tmux status line or a wrapped prompt in view. You can drag the keyboard from there; its position is remembered on that device.
  • Full keyboard puts the app's full keyboard Behind the terminal, the default, where the terminal's background is see-through and the text stays solid over the keys, or In front of it, where the keyboard is see-through. Behind needs graphics acceleration; without it the keyboard is in front.
  • Keep new terminals turns on Keep for every new terminal on this server, so leaving one does not close it. Off by default. It applies to new terminals only; Keep, in a terminal's header, changes it for that one terminal.
  • Scrollback is how many lines of history are kept.
  • Remote command runs in the terminal instead of your shell. Browsing files does not use it.

Under Advanced: TERM, the keepalive in seconds, and the environment variables for the server, one NAME=value per line. A name containing password, passphrase or secret, such as DB_PASSWORD, is refused, because these settings travel with the server between devices. The line above Save says 1 problem: Environment and Save stays off until the name is removed. Set that variable on the server instead.

These settings are sent along when you export the server. How the terminal uses them is in the terminal.

Where ~/.ssh/config is read

Only through the SSH alias box. With it filled, the dial looks that name up in ~/.ssh/config as ssh does, every matching block included. With it empty, the file is never read for that server, not even Host *, and a Host that matches a Host line is still just a host name. Key files from "alias" on under Login is a login you choose, like a password or a key. A new server starts on a password, or on Key files from "alias" once its alias names a key file that is on this device, as choosing that file's path would; any login you pick yourself stays.

Both boxes can be filled: the host then comes from Host, and the rest from the alias, as ssh -o HostName=other alias does. A ProxyJump host must be plain, [user@]host[:port] or an ssh:// address, with brackets only around the whole host, and on the last hop of a list only, no user or host starting with -, no % (which ssh expands) and no / in a host out of brackets (which ssh refuses), though a user may have one. A user or host may have =, : (in a host, in brackets only) and ~, but not a ~ a shell would expand — one that starts it, or in name=… one after the = or after a : (u=~root is a home folder, u:~root is not) — nor an = that starts it. One written with quotes, spaces or shell characters is refused with a message rather than read as ssh's shell would read it. Blanks may come before a port's digits (hop: 22), but not inside the hops before the last comma, which ssh hands its shell as one word. As in ssh, host: is the default port, ssh://[host] is the host in the brackets, ProxyJump none with anything after it on the line is a jump host called none, and a none that starts a list of two or more is no hop at all. A jump host named in a ProxyJump that is not one of your servers is dialled as ssh would dial it. The SSH alias box itself takes one name as ssh name would: not user@name, an ssh:// address, or a name with spaces or shell characters in it.

How a server logs in

Login is one list: Password, A key, and on a desktop SSH agent, Key files from "alias" and Path to an SSH key. Choosing a row chooses that login; Save keeps it, and Close discards the choice. The row the server is saved with has a current tag, and one chosen and not yet saved has a chosen tag. What goes with the chosen row is under the list, so the list itself never moves.

  • Password shows the password box.
  • A key reads Key "name" once a key is chosen, and opens a list of the keys on this device, each with its type and whether this app made it or it was imported, then New key…, Import a key file…, Paste a key code… and Manage keys ›. A key made, imported or received from here comes back chosen. A key the server names that is not on this device is listed, greyed. Under the login list the chosen key is named, with its type, where it came from and which servers use it, then its passphrase.
  • SSH agent (desktop only): picking it switches the server to the SSH agent this machine already runs, which signs for it — ssh-agent on Linux and macOS, the OpenSSH Authentication Agent or Pageant on Windows. Its keys are listed under the row. Any key the agent holds tries them in turn; choose one key instead where the agent holds more than the server allows tries. Copy Public Key copies a key's public line, for a server's authorized_keys. The agent asks for its own passphrases, so nothing is asked or stored here.
  • Key files from "alias" (desktop only), where the server has an SSH alias whose ~/.ssh/config entry names IdentityFile: picking it switches the server to those files, tried in order and read from that file at each connect. IdentitiesOnly, IdentityAgent and CertificateFile there are followed.
  • Path to an SSH key (desktop only): picking it switches the server to a key file on this machine, given by its path, with Browse beside the box. An encrypted file has a passphrase box for this server. Another server that uses the same file keeps its own. Where the SSH agent holds the file, the agent signs and nothing is asked while it does; a passphrase saved here is used only when it does not, and the box says so.

Choosing a key never breaks the login that works. While the choice is not saved, the card says Logs in now with the login in the file, then Chosen but not tested with Install it now and Use "name" for this server:

  • Test, in the bar, tries one login with what is on screen, which is the chosen key. Nothing is saved. If it works, the card says Chosen and tested; press Save to keep it. If it fails, the line above the bar names the refused key: the server does not have its public key yet.
  • Install it now adds the public key to the server's ~/.ssh/authorized_keys, logging in the way that works today (a password, or a key that already works), then switches the server to the new key. It asks only for what that login needs: the password, or the current key's passphrase, or nothing if it is saved. It also saves your other changes to the server. If the install fails, the server still logs in as before. It is for keys this app made.
  • Use "name" for this server is for when you know the server already has the key. The app does not check.

You can save at any time. On a server already saved, Save keeps the login that works today until something gets in with the new key — a Test that logs in, Install it now, or Use "name" — and saves your other changes. The card goes on saying Chosen but not tested, the bar says the rest is saved and the key is only chosen, and Close leaves the key unused on this device.

After Use and Save (or a first Save of a new server), the file names the new key, and keeps the password or passphrase of the login that works today until something has logged in with it. Until then the card says Saved but not installed. A connection tries the saved key first. While the server refuses it, a kept password still gets in, so the server stays reachable; Test still says the key was refused. A password asked at every connect is not kept, so there is nothing to fall back on, and Install asks for it once. Where the previous login was a key, Install still logs in with that key, and asks for its passphrase if none is saved. Where it was the SSH agent or the alias's key files, Install still logs in that way.

A key this app holds has a passphrase that is the key's, shared by every server that uses it, so it is not typed under a server's Login: the line under the keys says whether it is saved, held until the app closes, or asked at connect, and Key details › opens the key. A key file chosen by path is the exception above: its passphrase is kept for that server, and typed under Login.

On a phone, a server that came from a desktop with a key path, the SSH agent or an alias's key files shows that row greyed, with desktop only, since a phone has none of them. The same goes, on any device, for a server whose key is not on this device. Login says why, and Save and Test stay disabled, with the reason above the bar, until you choose a login this device can use.

The agent is used only where you choose it, with one exception that asks for less rather than more: where the agent already holds the key a server names, the agent signs with it, and the key's passphrase is not asked for while the agent holds it. A passphrase saved for that key is used only when it does not. A certificate beside a key file (id_ed25519-cert.pub) is offered before the key, and shown on the key's screen under Keys; an expired one is not offered. A key on a security key (ed25519-sk) works through the agent: add it with ssh-add, and touch the key when the app says the agent is waiting.

A server that takes only keys says so when you connect, instead of asking for a password it would refuse. Choose a key for it. A server that wants a key and then a password (OpenSSH's AuthenticationMethods publickey,password) offers only the key at first, so it reads the same way: with a key chosen, the password is asked for after the key is accepted.

Where passwords are kept

Never in servers.toml, the list of servers. Login tells you where before you type anything:

  • On a desktop: in the system keyring (Keychain, Credential Manager or Secret Service). A passphrase for a key this app holds is saved once for every server that uses that key, under Keys. A passphrase for a key file by path, or for an alias's key files, is saved for that server.
  • On Android: encrypted with the Android Keystore. On a phone where the Keystore will not open, in a file only this app can read, not encrypted, and excluded from backups and device transfers; anyone who can unlock or root that phone can read it. The form says which, where you type.
  • Where there is no keyring (a Linux machine without Secret Service, or WSL): a secret is kept until the app closes, and asked for again next time.

If you leave the box empty, you are asked when connecting. That box has two buttons: Connect uses the secret once, and Save and connect also keeps it. Pressing Enter is Connect, so it never saves anything. Save and connect is not offered where there is nowhere to keep a secret, or for a one-time code.

A secret that works is also held in memory until the app closes, so a connection that has to reconnect does not ask again. One used with Connect and not saved shows as held until the app closes in the form, not as stored.

Forget it appears beside a saved secret. It removes the secret from this device and closes the connection it opened, so it cannot keep working. The box then says it will ask when connecting, since a saved secret is never shown.

Keys

Keys, beside Servers at the top of the list, lists every key on this device, each with its type, its kind, which servers use it, and whether it has a passphrase:

  • A key this app made: kept in the app's own storage. It is the only kind included when you export servers.
  • A key you imported: a copy of a key file, often a .pem from a cloud provider, kept in the app's own storage under its file name. It is never included when you export servers, but it can be sent on its own as a key code.
  • A key file on this machine, such as ~/.ssh/id_ed25519, listed while a server uses it by path: used where it is and never copied. Desktop only.
  • A key a server names that is not on this device, so you can see what is missing.

On a desktop, the keys the SSH agent holds are listed under them, each with Copy Public Key; the agent keeps its keys, so nothing else is offered.

From a server, Key details › and Manage keys › open Keys over it. The bar at the bottom then reads Continue with and the server's name, and takes you back to it with its changes still there; Not saved yet above it says there are some.

A key's own screen has:

  • Its fingerprint, SHA256:… as ssh-keygen -l prints it, and its comment, to tell it apart from another key.
  • Its public key, safe to share, with Copy Public Key for adding it to a server yourself, and a certificate beside it if there is one: valid, or amber where it has expired, is not valid yet, or is for another user. A certificate is offered before the key alone.
  • Its passphrase, for a key this app holds: none, saved, or asked at connect. Save keeps one, checked against the key first, for every server that uses it. Forget it asks first and names those servers, since their connections close. Where the SSH agent holds the key, it signs and nothing is asked while it does; a passphrase saved here is used only when it does not. A key file on this machine keeps its passphrase with each server, set under that server's Login.
  • Used by: the servers that log in with it. Tap one to open it.
  • Copy Private Key… offers two ways to take the private key off this device:
    • Show it as a QR image, for another device running Telechore to scan. You can set a password for it, of any length or none, and type the same one on the other device. The password is the only protection if someone photographs the QR image, and the box says so when it is empty. A saved passphrase for the key goes with it.
    • Copy it to this device's clipboard, only for a key this app made. The key is not encrypted, and clipboards may keep a history or sync to other devices, so use the QR image to reach another device. This is for pasting into a program on this machine.
  • Install on a server… adds the public key to a server you choose, logging in the way that server does today, and switches it to the key. A server that already uses the key, one open with unsaved changes, or on a phone one this device cannot log in to, is greyed. For keys this app made.
  • Remove key "name"… deletes the key from this device and cannot be undone. It is greyed while a server uses the key, with which servers under it: move them to another login first. Never offered for a key file on this machine.

Under the list:

  • Generate a key makes a new key on this device. It asks for a name and a passphrase; leaving the passphrase blank is fine, since only this app can read the key file. No server uses it until you choose it. To replace a key, generate a new one, use Install on a server… for each server, and remove the old one when nothing uses it.
  • Import a key file… copies a key into the app. On a phone it is the only way to use a key file, since access to a picked file does not last. An encrypted .pem cannot be read without its passphrase, so it is asked for. Then Keep it saves that passphrase with the key, for every server that uses it, and Ask at connect stores nothing.
  • Paste a key code… (Scan or paste a key code… on a phone) receives a key from another device running Telechore. It shows what arrived and the name it will be saved under; Keep the key saves it, with its passphrase if any.

A key code can carry a key you imported; a configuration code never does. Exporting servers sends only keys this app made, while a key code is one key you chose to send. Neither can carry a key file on this machine. A key keeps its kind on the other device: a key this app made can be sent on again, and an imported one is still never included when exporting servers.

Test and Disconnect

Test, in the bar at the bottom, logs in once with the settings as they are on screen, including unsaved edits, and says what happened above the bar. It saves nothing, so a working test still needs Save. It always makes a fresh connection, so the answer is about what is on screen now.

Disconnect is beside Connected in a server's summary, greyed while it is not connected. It closes the connection, and any terminal or file view using it stops; the next thing that needs the server logs in again. A folder left open says the server was disconnected, with Connect to log in again there. Terminals you left open stay listed, marked ended, and Reconnect in one starts a new shell. A connection also closes when its secret is forgotten. Replacing a secret, or changing which key the server uses, leaves what is open running; the next connection logs in with the new one.

Last connection

Every connection to a server leaves a short record of what it did, step by step: the address it reached, whether the host key is the one on record, what the server accepts, each login tried and what the server answered, and whether it offers file access. Its heading says how it ended and when: Logged in, or in red Refused, No answer and the like. The time a question waited for you, such as a passphrase box, is counted apart from the connection's own time.

You reach it three ways: Details after a Test; Details in the box that says a server's folders could not be reached; and in a terminal that could not connect, where the record is printed, dimmed, under the error. Closing a password box or declining a host key prints nothing.

Copy puts the record on the clipboard as plain text, to send to whoever looks after the server. It holds the address, the user name, key names and the host key's fingerprint. It never holds a password, a passphrase, a code, anything you typed, or the server's own messages. Only the latest connection to each server is kept, and only until the app quits.

Host keys

The server's identity is checked as in any SSH client. A new host asks you once. A host whose key has changed is refused, and the message shows the old key.

New hosts are saved in the app's own file; the one ssh uses is never changed. On a desktop, ~/.ssh/known_hosts is also read, so a host you have used from the command line does not ask again. A phone has no ~/.ssh, so every host is new the first time. Hashed host names, the default on Debian and Ubuntu, are read too.

Two kinds of line are treated specially:

  • A key marked @revoked is refused. If the revocation is out of date, remove that line from the file that holds it.
  • @cert-authority lines are not used, because this app does not check host certificates, and an import does not copy them.

A host with two keys of the same type on file, which is normal after a server is re-keyed, is accepted with either one.

The file behind the list

The list is servers.toml, in the app's configuration folder beside known_hosts and the keys. It is TOML, starting with version = 1, with one [[server]] block per server. You can edit it by hand, or copy it to another computer, since it holds no secrets.

It includes the [server.terminal] table from the Terminal part, which holds only the settings you changed. Anything the app does not recognise, such as a misspelt name or a newer setting, is kept when the editor saves.

The old layout

The Servers page as it was before 0.5.1 is still in the app until 0.6.0. Switch to the old one, at the foot of the server list, opens it on this device, and Switch to the new one, at the foot of the old one, comes back.
